## Shipping UI dependencies

There is no Unity Editor executable or exact 6000.3.10f1 managed reference bundle in this environment. No PanelSettings/ThemeStyleSheet serialized YAML or built-in shader GUIDs were guessed.

`Docs/PRODUCTION_UI_DEPENDENCIES.json` records the seven shader fields/names initialized by the exact target Editor's PanelSettings source. `ProductionUiDependencies.Prepare()` runs in the ordinary `PipelineBuild.OnPreprocessBuild` callback before production validation. It:

1. Imports a real TSS using Unity's own default runtime theme template, `@import url("unity-theme://default");`.
2. Uses `AssetDatabase.CreateAsset` to create a native serialized `PanelSettings` under `Assets/Crownfall/GeneratedUI/Resources/CrownfallProductionPanel.asset`.
3. Binds the imported theme and all seven actual Shader object references through `SerializedObject`.
4. Appends those shaders to Graphics Settings' `m_AlwaysIncludedShaders`, preserving existing entries and avoiding duplicate additions. This retains runtime variants even though the HUD/materials are constructed dynamically.
5. Saves the native assets/settings and validates the persisted references, resolved theme import, Resources binding and Always Included entries. Missing fields, shaders, imported themes or version mismatches abort the build.

`ProductionHud` loads that serialized Resources asset, clones its mutable per-session settings, and binds the UIDocument to the clone. It shares the retained theme/shaders and never creates an empty runtime theme/panel. Absolute UI placement explicitly zeros theme margins to preserve the existing control rectangles.

Native generated assets and their GUIDs are intentionally generated by the required Editor and ignored in Git; the specification and preparation/validation code are committed. **The preparation/import/serialization has not been executed here.** For local Editor play, first run **Crownfall → Prepare Production UI Dependencies**. The build callback performs this automatically before export. `ProductionArtValidation.Validate()` independently rejects absent/broken native bindings.

Static current-build/production validation checks the exact dependency specification, shipping binding, preparation order and persisted-retention operations. Twelve negative checks prove that removing the theme, a shader, panel binding, preparation, native asset creation, reference assignment, Always Included insertion, saving or validation fails the source gate. These are source-contract checks, not native import or shader-export certification.
